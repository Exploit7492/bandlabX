## What was done

The design leaf. Its job was to turn the evidence into a resource design and resplit Phase 3.
While doing it, a **stronger evidence source was found and used**, which changed the numbers.

1. **Found and used a stronger evidence source (rule D13).** The bundle proves paths but not
   shapes. The **shipped Android app** proves both: it calls the same API through Kotlin
   interfaces, and because it uses kotlinx.serialization its serializer descriptors preserve the
   **real** class and field names even though the dex is obfuscated. Decompiling it with jadx
   yields paths, host groups, auth flags, verbs and response shapes, with no account and no
   capture. Recorded in `docs/research/APK-EVIDENCE.md`.

2. **Recovered the endpoint surface.** 170 service interfaces, 587 methods, 401 path templates,
   of which **344 are BandLab API paths the SDK does not expose**. Every one has a verb;
   **265 (77%) have a real response shape**. 1,094 model classes with 1,973 distinct JSON field
   names. Output: `docs/research/apk-endpoints.md` and `docs/research/apk-shapes.tsv`.

3. **Derived the verb map and validated it.** The path annotations are obfuscated and their verb
   is not printed anywhere in the dex, so it was derived from method names (which Kotlin does not
   obfuscate) and checked two ways: against the OpenAPI spec, where the map agrees on every
   single-verb path, and by in-file coherence in `SamplesService`, which fixes `@lik` = PUT.
   Confidence per annotation is in `APK-EVIDENCE.md` §4.

4. **Resolved the host groups.** The `j11` constant is obfuscated in the field position but its
   enum name is intact in the static initializer, so all 44 groups resolve exactly. This is what
   evidences the mobile/studio hosts (`SAMPLES`, `SOUNDS`, `SOUND_BANKS`, `PALETTE`, and the AI/ML
   groups) that the bundle could not reach.

5. **Wrote the design.** `docs/handover/RESOURCE-DESIGN.md`: all 344 paths assigned to exactly one
   of **35 resources**, each with its target file, accessor and type strategy. 14 extend an
   existing file, 21 are new. No path is unassigned.

6. **Resplit Phase 3 and raised M.** 26 domains / 52 leaves became **40 domains / 80 leaves**;
   Phase 4/5 renumbered. **M raised 73 → 101.** Regenerated the checklist in `HANDOVER.md`, the
   leaf specs in `TASKS.md`, and `COVERAGE.md` section 4.

7. **Investigated the owner's subscription request and recorded the finding.** Gating is
   server-side; the app holds only presentation state and delegates purchase to
   Purchasely/Google Play. Added rule **D14** (no entitlement bypass; expose the full free surface
   and membership/quota read-only instead) and rule **D15** (exclude third-party SDK surface).

8. **Added a reproducible extractor.** `scripts/research/apk-to-endpoints.py`, stdlib only, so any
   session can regenerate the artifacts from a jadx output tree.

## Deviations

- The leaf spec said "201 new endpoints"; the evidence shows 344 BandLab paths. The spec line was
  rewritten rather than followed, and M was raised.
- The leaf was expected to be docs-only; it also added one Python extractor under
  `scripts/research/`, which rule D5 permits for evidence tooling.
- **Correction made in a later pass:** the first extraction excluded the whole `/experiment/`
  path namespace as third-party. That was wrong: BandLab serves real endpoints there
  (`/experiment/users/{id}/membership-status`, `/experiment/beats/{id}`,
  `/experiment/feeds/communities/posts`, `/experiment/users/{id}/purchases/beats`,
  `/experiment/beats-filters`), on BandLab hosts. Exclusion is now **by host group**
  (`AMPLITUDE_EXPERIMENT`, `AMPLITUDE_ANALYTICS`, `BRANCH` = 9 paths) and never by path segment;
  the five `/experiment/` BandLab paths are kept with the prefix stripped for routing. Rule D15
  was tightened to say so. Totals moved from 353/272 to **344 BandLab paths / 265 shapes** (the
  nine third-party paths, formerly inside the 353, are now counted separately).
