## Generators

`api.md` is generated, not hand-edited, so it can be rebuilt and diffed:

- `scripts/research/gen-31-api.py` — leaves 15–40.
- `scripts/research/gen-32-api.py` — the 3.2 resources.
- `scripts/research/gen-33-api.py` — leaves 63–90.

Each generator reads the `*Params` interfaces and method signatures out of `src/resources/**` and
emits the matching `api.md` rows, so a method added without a row (or a row without a method) is a
regeneration away from being visible.

## Verification tooling added

- `scripts/research/evidence-coverage.py` — pairs every path in `docs/research/apk-endpoints.md`
  with a `this._client` call in `src/resources/**`. Result: **evidenced 341, covered 341,
  remaining 0**. Two rows (`GET /validation/band`, `GET /validation/user`) are served by the
  generic `validation.validate(entityType)`, recorded through a `COVERED_BY_GENERIC` exception.
- `scripts/research/sync-endpoint-status.py` — merges the `./scripts/coverage --markdown` seed into
  `docs/endpoint-status.md` while preserving every Status that was set by hand, and takes `apk` /
  `apk-path-only` for new rows from `docs/research/apk-endpoints.md`. The file's own header says it
  must never be regenerated wholesale; this is the tool that respects that.
- `scripts/research/gen-31-tests.py` — extended to emit evidence tests for the 3.2 and 3.3
  resources. It now scopes the `*Params` lookup to the owning class, which is what nested messaging
  classes need (`ReadReceipts.list` was picking up an unrelated interface and building a path with
  `undefined` segments).
