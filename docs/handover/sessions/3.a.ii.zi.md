obfuscated) and `updateContour` (same). `retrieveDownload` takes only the evidenced `format` value.

## The `/revisions/{id}` route collision

`retrieve` and `retrieveDownload` share `GET /revisions/{id}`; the app tells them apart by
`?format=m4a`. The SDK keeps both as separate methods, and the evidence test asserts that
`retrieve` sends no `format` while `retrieveDownload` sends `format=m4a`.

`scripts/research/har-to-endpoints.py` keys its table by verb+path, so the two rows collapse to one
(133 keys from 134 rows). `test_har_to_endpoints.py` pins this: the count moved 125 → 133, not 134,
and the collapsed key resolves to `client.revisions.retrieveDownload()`.

## `contour` placement

`PATCH contour/{projectID}/{regionID}/{activeSampleID}` is the one path in this leaf that is not
under `/revisions`. `RESOURCE-DESIGN.md` assigns it here, so it ships as `revisions.updateContour`
rather than a one-method resource. This is a recorded design choice, not an inference about the API.
