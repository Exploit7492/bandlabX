### The `4.a.ii.zo` follow-up — a loader bug

Re-deriving the audit numbers turned up a real defect in the audit tooling. The status-table loader
in `scripts/research/har-to-endpoints.py` used

```python
r"^\| `(\w+)` \| ([A-Z]+) \| ... \|$"
```

`\w+` cannot match `apk-path-only`, so **all 73 `apk-path-only` rows were invisible**. The test that
guards this file pinned `len(table) == 381`, and that number had been derived from the buggy parse,
so the test passed while a fifth of the table went unread. The single literal spaces were a second,
latent problem: `./scripts/format` runs Prettier over `docs/endpoint-status.md`, which pads the
columns, so after a format **every** row stopped matching.

Fixes:

- `STATUS_ROW_RE` now allows `[\w-]+` for the status and `\s*` around the pipes.
- `test_har_to_endpoints.py` pins 454 (468 rows, 14 collapsed) and asserts an `apk-path-only` path
  resolves, so the regex cannot silently lose a status kind again.
- `sync-endpoint-status.py --check` compared raw text against its own unpadded output, so it reported
  "out of date" for a file Prettier had merely reformatted. It now compares parsed rows and the
  summary line.

No endpoint was mis-implemented: this was a measurement bug. After the fix the counts agree three
ways — `src/resources/**` has 459 `this._client` calls, `api.md` has 468 rows, and
`docs/endpoint-status.md` has 468 rows over 454 distinct verb+path keys.

## Bugs found and fixed while writing the workflow

- **Buildx rejects `push` and `load` together.** The first draft asked for both. The job now builds
  into the local daemon, smoke-tests that image, then pushes the same tags.
- **GHCR rejects uppercase image paths.** The owner is `Exploit7492`, so
  `ghcr.io/${{ github.repository }}` would have failed every publish. The workflow lowercases it.
- **`metadata-action`'s `version` output need not equal any generated tag.** The smoke step now takes
  the first line of `tags`, which is guaranteed to be a tag the build actually loaded.
